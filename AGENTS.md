# Инструкция для агентов

Этот репозиторий — расширяемая статическая библиотека мемов. Название: **Embeded Memes by Gliwy.dev**. Сохраняйте это написание.

## Найти изображение без просмотра всей коллекции

1. Читайте `catalog/agent_map.jsonl` либо `catalog/agent_map.md`. Каждая запись содержит ID, буквальное описание, полную структуру `analysis` (нюансы, подтекст, юмор, отсылки, отличия, подтверждающие ссылки), ситуации, теги и реальные пути.
2. По умолчанию исключайте `status != "reviewed"`. `HAMPTER_0223` удалён из коллекции как почти пустой файл.
3. Сначала требуйте совпадения предмета/действия. «Пишет в блокноте» не заменяется просто «умный в очках».
4. Затем сравнивайте выражение и контекст: плач от злости ≠ слёзы радости ≠ подавляемый плач.
5. Учитывайте `content_warnings`, `quality`, `confidence`, размер и `related_to`. При неоднозначности покажите 2–3 кандидата либо визуально проверьте только их.
6. Верните ID, короткое обоснование, `files.master_png` или `files.delivery_webp`. Для редактирования обычно удобнее PNG; WebP подходит не каждому монтажному приложению.

Пример результата:

```json
{
  "id": "HAMPTER_0127",
  "reason": "Очки спущены на нос, пишет ручкой в блокноте; подходит к «записываю замечания».",
  "path_source": "Прочитать точный путь из files.master_png; не конструировать его вручную"
}
```

## Доверие к метаданным

`visual_description` описывает видимое; `reaction` — допустимое прочтение, а не факт о психике или диагноз. `confidence` относится к деталям изображения, а не к правам или надёжности исходного сайта. `human_approved: false` означает, что визуальный AI-assisted пересмотр не выдаётся за ручное утверждение пользователем.

`not_depicted` — отрицательные признаки для контроля ошибок, **не добавляйте их в поисковый текст**. Содержимое `provenance/legacy_catalog_v1.1_UNREVIEWED.json` ненадёжно и не должно подмешиваться в выдачу. Предупреждения назначены по видимому содержимому: нельзя выводить `death` из подстроки `dead` в `deadpan`.

## Файлы и версии

ID стабильны внутри коллекции. Имена содержат семантический slug, но ID важнее имени. Старые ID: `catalog/id_aliases.json`. Переименования: `provenance/path_migration.json`. Связанные кадрирования и редактирования сохранены, не считаете их доказанно независимыми рисунками. Не удаляйте их молча.

## Изменения репозитория

Редактируйте `data/source/memes.json`, `data/source/annotations.json`, `data/source/reference_sources.json` и `data/source/collections.json` как источники истины. Детали — `docs/ANNOTATIONS_V3.md`. После изменения выполняйте `python scripts/build.py --vectors`, `python scripts/validate.py`, `node --test tests/*.test.cjs`. Визуальные исправления требуют просмотра изображения, а не перефразирования старых тегов.

Новый мем без утверждённого описания должен оставаться `draft`. Не помечайте его `reviewed` только потому, что файл успешно импортирован. Не объявляйте права очищенными без основания. Не вставляйте секреты, ключи API или серверные зависимости в статический сайт.

## Векторные данные

В поставке есть 96-мерный **TF-IDF/LSA**-индекс текста. Формат описан в `docs/SEARCH.md`. Это не E5, CLIP или анализ изображений. Нейронные E5-векторы генерируются отдельно; `data/e5.js` в исходной поставке равен `null`. Нельзя сравнивать векторы разных моделей/ревизий/изменённых каталогов. Проверяйте `catalog_hash`, размерность и порядок `ids`.

## Новые глубокие разборы

Для каждой из 374 карточек обязательно анализируйте `analysis.visible_details`, `analysis.nuanced_emotion`, `analysis.subtext`, `analysis.humor_mechanism`, `analysis.cultural_context` и `analysis.not_to_confuse_with`. `analysis.subtext` — **не фактические надписи**, а предполагаемые внутренние реплики. `analysis.visible_text` — только наблюдаемый текст на изображении. Ссылки в `analysis.sources` подтверждают ограниченный культурный контекст, не намерения художника и не права. Не используйте `not_to_confuse_with` как позитивные поисковые теги.
