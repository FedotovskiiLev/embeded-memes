# Поиск: что действительно вычисляется

## 1. По словам

`src/search.js` нормализует регистр и `ё/е`, выделяет русские и английские токены и снимает некоторые окончания. Это небольшая эвристика, **не полноценный морфологический анализатор**. Общие служебные слова исключаются. BM25-подобная оценка использует длину документа и частоту термина; заголовки, теги и ситуации повторяются с весом при построении текста. Точные фразы получают дополнительный приоритет. Для отсутствующего слова длиной от четырёх символов предусмотрено расстояние редактирования до одного символа.

Небольшой открытый словарь понятий в `scripts/search_config.py` связывает «конспект», `notebook`, «записываю»; «кислород», «дышать», `oxygen` и т. п. Это правила, а не нейросеть. Фильтры тем/эмоций тоже получены из этого словаря; они не являются независимой экспертной оценкой.

## 2. Готовый локальный векторный индекс

Для каждой активной карточки собирается текст из новых полей. Прежние теги, URL источников, технические пути, `not_depicted` и карантин не участвуют. TF-IDF использует `tf=1+ln(count)`, `idf=ln((1+N)/(1+df))+1` и L2-нормализацию. Затем `TruncatedSVD`, 96 компонент, `random_state=42`, и повторная L2-нормализация. Это **Latent Semantic Analysis (LSA)**.

Запрос преобразуется тем же токенизатором, словарём, IDF и матрицей проекции. Косинусное сходство дополняет лексическую оценку. При запросе сразу на несколько понятий учитывается их покрытие, чтобы «злится и плачет» не сводилось к обычной злости. Точный ID и старый alias имеют отдельный приоритет. Очень слабые хвостовые совпадения отсекаются.

Встроенные «похожие» также означают сходство описаний, не пикселей. Из двух похожих лиц нельзя вывести одинаковый смысл без описаний. LSA обучена на небольшой конкретной коллекции, ограничена её лексикой и хуже нейромоделей понимает новые длинные перефразы.

### Формат файлов

- `data/lsa.js`: модель в `window.EM_LSA`; работает без сетевых запросов.
- `data/embeddings/lsa.json`: та же информация для внешних инструментов.
- `lsa-vectors.f32`: little-endian float32, row-major, `count × dimensions`; строки соответствуют `ids` манифеста.
- `lsa-projection.f32`: `vocabulary.length × dimensions`, тот же тип и порядок.
- `lsa-manifest.json`: размерность, ID, тип модели, хэш каталога, объяснённая дисперсия.

В JSON бинарные массивы представлены Base64; `vocabulary` и `idf` описывают проекцию. Браузер не использует индекс с другим `catalog_hash`. При воспроизводимой пересборке численные значения могут незначительно отличаться между библиотеками/платформами, даже при фиксированном seed.

## 3. Необязательный нейрорежим E5

Модель: `Xenova/multilingual-e5-small`, ONNX-версия `intfloat/multilingual-e5-small`. В интеграции закреплена ревизия `761b726dd34fb83930e26aab4e9ac3899aa1fa78` и Transformers.js `3.7.6`; это намеренно фиксированные версии, а не заявление о самых новых. `dtype: q8`, размерность 384, mean pooling, L2-нормализация. Для описаний используется префикс **`passage: `**, для запросов — **`query: `**, в том числе на русском.

### В браузере

Открыть через HTTP(S) → «Нейропоиск» → согласиться на загрузку. Worker скачает библиотеку, модель и токенизатор, затем рассчитает векторы описаний или возьмёт совместимые предварительно рассчитанные. Результат сохранится в IndexedDB по модели, ревизии и хэшу каталога. Один WASM-поток выбран для работы без специальных заголовков COOP/COEP на обычном Pages. Не закрывайте страницу во время расчёта; «Остановить» завершает worker. Есть JSON-экспорт готовых E5-векторов.

Модель не получает картинки: она обрабатывает текст. На сервер не отправляются тексты запросов или карточек для inference; первая загрузка файлов обращается к Hugging Face и jsDelivr. Браузерный HTTP-кэш и IndexedDB могут быть очищены, ограничены или недоступны. Офлайн-работа после первой загрузки зависит от сохранности этих кэшей.

### Предварительный расчёт

```bash
npm install
npm run embed
```

Нужны Node.js 20+, доступ к npm/Hugging Face и место для весов/кэша. Выход: `data/e5.js`, `data/embeddings/e5.json`, `e5-manifest.json`. Коммитьте эти результаты, но не `.cache/`. Даже с готовыми векторами документов браузеру всё ещё нужна модель, чтобы векторизовать новый запрос. При изменении каталога пересчитайте индекс. Матчинг не смешивает векторы от разных ревизий.

**Граница проверки этой поставки:** веса E5 не удалось скачать в среде подготовки; полный inference и сетевое поведение на реальном Pages не проверены. В поставке `window.EM_E5 = null`. Нейроадаптер помечен экспериментальным, а основной локальный индекс построен и проверен. Не выдавайте наличие адаптера за готовые нейронные эмбеддинги.
